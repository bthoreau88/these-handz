## Combat audit rubric — teach / test / twist adapted to a finger-fighter

1. **Teach**: player learns a tap/light, swipe/medium-or-dash, down/low, block, parry and buffered special in a predictable, low-pressure context. Confirm with a human participant and unprompted demonstration rather than checking whether UI text exists.
2. **Test**: establish whether the player can intentionally use an input under an opponent's pressure, distinguish distance-dependent dash vs medium, and recognize the startup/active/recovery exchange. Record misses and accidental activations.
3. **Twist**: vary relative facing, corner position, opponent defense, combo timing, or approach distance **without replacing the learned rule**. Test whether comprehension transfers to mirrored sides and later exchanges.
4. **Judge**: replay recorded scenarios and visually inspect the same position/camera. Human review must answer whether damage feels fair, reactions are legible, animation communicates impact and sound supports the action. Automated code checks are supporting evidence, not an experience rating.

## Capture and regression rules

- Fixture names are `neutral_opening`, `mid_range`, `wide_separation`. Each shot stores fighter IDs, positions, camera position/zoom, actual image dimensions and SHA-256.
- Compare the **same fixture**, viewport size, Godot/render version and platform; never score a screenshot captured in a different state or at an unknown camera pose.
- Pixel changes trigger **REVIEW**, not quality scores. A visually better lighting pass may have a larger pixel difference than a regression.
- A capture missing from either side is **NO EVIDENCE**, not “unchanged.”
- Human reviewers should record pose legibility, hand silhouette, foreground/background separation, HUD contrast, grounding, camera framing, temporal continuity and any trademark contamination.
- Any forced repositioning or synthetic input is labeled simulation and cannot certify genuine player performance.
